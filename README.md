# 🎯 Recruiter Copilot — QLoRA-Fine-Tuned Resume ↔ JD Fit Assessor
A 1.5B-parameter open-source LLM, fine-tuned from scratch with **QLoRA**, that reads a resume
and a job description and returns a structured fit assessment — not just a label, but *matched
skills*, *missing skills*, and a one-sentence, human-readable rationale.
 
```json
{
  "matched_skills": ["python", "sql", "communication"],
  "missing_skills": ["kubernetes", "risk management"],
  "verdict": "Strong technical alignment on data tooling, but lacks the infra/DevOps experience the role emphasizes.",
  "fit": "Potential Fit"
}
```
**Built entirely on free infrastructure — $0 spent.** Google Colab's free T4 GPU for training,
Groq's free API for data distillation, Hugging Face for the dataset and model hosting.
 
---

## Why this isn't just another "resume matcher"
 
A handful of LoRA-fine-tuned resume/JD classifiers already exist for this exact dataset. This
project is deliberately built differently, in two ways:
 
1. **It's not a classifier — it's a structured reasoner.** The model doesn't just emit a label;
   it generates matched/missing skills and a rationale sentence, then commits to a fit verdict
   *after* laying out that evidence — closer to how a human recruiter actually reasons than a
   single softmax over three classes.
2. **The training data itself is distilled, not scraped.** The one-sentence rationales the model
   learns from were generated by prompting a much larger free model (Llama-3.3/3.1 via Groq) on
   1,500 resume/JD pairs, then verified and cleaned before training — a real, small-scale
   knowledge-distillation pipeline, not just an API wrapper.

## Pipeline
 
```
Dataset (HF)  →  deterministic skill extraction  →  LLM-distilled rationale (Groq, offline)
     ↓
instruction-formatted training set (resume+JD → structured JSON)
     ↓
QLoRA fine-tune (Qwen2.5-1.5B-Instruct, 4-bit, LoRA adapters)  →  evaluation  →  Gradio demo
```

| Stage | Tool | Cost |
|---|---|---|

| Skill extraction | Custom keyword-matching against a 70+ term skill vocabulary | Free |
| Rationale distillation | Groq API, `llama-3.1-8b-instant` (1,500 calls) | Free tier |

| Hosting | Hugging Face Hub (adapters) + Spaces (Gradio demo) | Free |

### What iterating on this taught me
 
The most interesting part of this project wasn't the first training run — it was figuring out
*why* it didn't work and fixing it with a real architectural change, not just more compute:
 
- **v1** (rank-16 LoRA, `fit` as the *first* JSON key): low training loss, fluent verdicts, but
  only ~30% label accuracy — barely above chance on a 3-class problem.
- **Diagnosis:** tested the model on training examples it had directly seen and it *still* got
  the label wrong most of the time. That ruled out overfitting/generalization — the model
  genuinely hadn't learned the label signal, because `fit` was the shortest field and generated
  first, before the model had "reasoned" through any evidence, while the much longer
  `verdict`/skill fields dominated the training signal.
- **v2:** doubled LoRA rank/capacity and epochs — validation loss improved a lot, but label
  accuracy *dropped* to ~17%. More capacity alone wasn't the fix; the model just got better at a
  different wrong pattern (defaulting to one label).
- **v3 (final):** reordered the JSON schema so `fit` is generated **last**, after
  `matched_skills`, `missing_skills`, and `verdict` — forcing the model to lay out evidence
  before committing to a label, similar in spirit to chain-of-thought prompting. This is the
  version reflected in the results table above.
This debugging process is worth more as an interview story than a clean first-try success would
have been — it demonstrates actually understanding *why* a fine-tune fails, not just running a
tutorial.

## How to run
 
1. Open `resume_fit_qlora.ipynb` in [Google Colab](https://colab.research.google.com), set
   runtime to **T4 GPU**.
2. Add a free [Groq API key](https://console.groq.com) as Colab secret `GROQ_API_KEY` (only
   needed if regenerating the distilled rationales — the cache is included so this is optional).
3. Add a free [Hugging Face token](https://huggingface.co/settings/tokens) as secret `HF_TOKEN`
   if you want to push the trained adapters to your own Hub account.
4. Run cells top to bottom. Training (Section 6) takes ~25–45 minutes on a T4.
5. `app.py` is ready to drop into a Hugging Face Space (Gradio SDK) for a live demo link.
